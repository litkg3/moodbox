# 情绪盒子 MoodBox

> 让情绪有处安放，让快乐有迹可循。

情绪盒子是一个治愈系情绪管理 Web 应用：12 颗不同颜色与重量的情绪球漂在页面上，选中哪一颗，就得到一段不说教的温柔回应 —— 也可以把它**捏爆**，看着它碎掉、从天上消失；生活里那些让你嘴角动了一下的小事，可以被收藏进「快乐收藏馆」、叠成纸条放进「开心罐」，在低落时通过「我不开心了」重新遇见。

除了情绪本身，它还留了几个出口：写给自己的心事信箱与时光信箱、跟着圆环呼吸、六道题的轻量测试、六篇治愈故事，以及一个**需要审核**的树洞广场 —— 在那儿可以说一句，也会有别人抱抱你。

它有两副面孔：白天是暖奶油色的玻璃房，夜里是一整片会亮的星空，跟随系统自动切换。

它不是心理测评，也不是要求你「变好」的工具。它更接近一个抽屉。

本项目为大学生软件设计竞赛作品，包含完整可运行代码、设计文档、架构文档与现场演示脚本。

## 一、主要功能

| 模块 | 说明 |
| --- | --- |
| 漂浮情绪球 | 12 种情绪（含迷茫 / 委屈 / 麻木 / 分别），独立配色、尺寸与漂浮轨迹；点击后球体放大、其余变暗 |
| 情绪陪伴 | 每种情绪 7~15 条原创中文文案（共 164 条），支持「再给我一点温暖」切换，不会连续重复 |
| 捏爆与飞回 | 面板里选「捏爆它」→ 球在主页粉碎消散，**2 秒后自己飘回来**；不做「手动召回」，释放不等于删除。提示语按情绪分两种：负向是「焦虑被你捏爆了！负面情绪释放成功」，开心是「开心被你捏爆了，好心情是会传染的哦」 |
| 看个小故事 | 面板里的第三个按钮：就地换成一篇内置故事，可以「换一篇 / 回到刚才」，不跳页、不开第二个弹层 |
| 记录此刻情绪 | 一键写入当天情绪记录，进入情绪足迹；仅保存在本地 |
| 开心罐（卡片） | 点导航即开，不跳页：玻璃罐 + 纸条清单 + 收藏表单 + 备份与隐私。收藏时直接点日历格子选日期，不再需要起名字 |
| 心事信箱（卡片） | 同一套卡片：写 → 封存 → 拆开 → 销毁；常驻求助热线，不需要等到关键词命中 |
| 情绪足迹 | 手账式月视图，情绪彩点 + 快乐星星，点击查看当日详情，支持在指定日期补记；页面底部并入「这一周」小结（记录天数、快乐份数、最常出现的情绪、逐日柱状与构成条），只用主动记录的数据 |
| 呼吸放松 | 4-4-6 舒缓 / 4-7-8 助眠两套节奏，圆环随呼吸缩放，随时可以停下来 |
| 情绪测试 | 6 个问题 → 映射到 12 种情绪之一，结果只留在当前页面，不写入任何记录 |
| 树洞广场 | 匿名发短帖，**先审核后展示**；其他访客可以拥抱（一个 IP 对同一条只能抱一次）和回复；出现自伤相关表达时先弹提示但不拦截。**可接 Supabase**，接上后数据跨设备共享，审核变成服务端校验 |
| 白日 / 星空 | 跟随系统 `prefers-color-scheme` 自动切换，也可以手动锁定；夜间为一整片星空，组件与白日完全同一套 |
| 背景音乐 | 可配置音源、音量、淡入淡出、循环、站内跨页不断播；音源缺失时明确提示且不影响其它功能 |
| 数据备份 | 开心罐卡片底部：导出 JSON（含图片）、合并导入、载入/清除演示数据、清空全部（逐项列出会删什么） |
| 无障碍 | 键盘可达、Esc 关闭、焦点陷阱与归还、`aria-live` 播报、`prefers-reduced-motion` 降级 |

## 二、页面地图与导航

站点只有 6 个页面，另有 2 个「卡片式功能」和 1 个页面内动作：

| 路由 | 页面 | 入口 |
| --- | --- | --- |
| `/` | 主页（情绪天空） | 页头品牌 / 移动端「主页」 |
| `/calendar` | 情绪足迹（日历） | 导航「情绪足迹」 |
| `/breathe` | 呼吸放松 | 导航「呼吸放松」 |
| `/quiz` | 情绪测试 | 导航「情绪测试」 |
| `/square` | 树洞广场 | 导航「树洞广场」/ 主页按钮 |
| `/about` | 关于 | 导航「关于」 |

| 卡片（无路由） | 说明 |
| --- | --- |
| 开心罐 | 原 `/jar` + `/memories` 合并成一张玻璃卡片 |
| 心事信箱 | 原 `/letters` 改成同一套卡片 |
| 清空数据 | 动作，不产生新界面，只弹一层确认 |

入口定义只有一份（`src/lib/tools.ts`，8 项），按屏幕宽度分两种呈现：

- **桌面端（≥1024px）**：页头**同一行**里的玻璃导航条（品牌 · 八项入口 · 主题/音乐），1280px 以上显示图标 + 文字，1024–1279px 只留图标靠 `title` 补名；页面底部不再有任何导航；
- **移动端（<1024px）**：页头右上角**只有「主页」「更多」两个按钮**（「更多」是整站唯一被填色的按钮，保证它一眼可见），八个入口连同主题、音乐都收进「更多」的玻璃面板。

早先那套「主页底部三簇 + 顶部横向轨道」的双导航已经删掉，只保留页面顶部这一处。

### 管理员与审核

树洞广场的审核走「管理员模式」：

- 广场页上**没有入口按钮**，手动访问 `/square/admin` 才会看到口令框；
- **同一台设备一天最多输错三次**，错满就锁到次日零点（计数存在 `localStorage`，
  是体验层的闸门，清掉存储即可重来，不构成安全边界）；
- 解锁状态只存在 `sessionStorage` 的**令牌**里（关掉标签页即失效），不写 `localStorage`；
- 口令是否正确由谁判断，取决于有没有接 Supabase：

| 模式 | 口令存在哪 | 校验在哪 | 能不能绕过 |
| --- | --- | --- | --- |
| 未接 Supabase（默认） | 代码里的 `DEMO_ADMIN_PASSCODE = 'moodbox2026'` | 浏览器 | **能**，改 `sessionStorage` 就能进 |
| 已接 Supabase | 数据库 `moodbox_config.admin_token` | `moodbox_is_admin()` 函数 | **不能**，界面解锁了也审核不动 |

界面文案会跟着变：本地模式明确写着"这个校验发生在前端，任何人都能绕过"；
云端模式写着"口令会送到 Supabase 校验，前端绕不过去"。**不制造安全感是这里的原则。**

访客能做什么：阅读、发帖、拥抱、回复、**删掉自己发的东西**。访客不能做什么：审核、拒绝、删除别人的帖子。
发帖的 `status` 在云端是**在数据库函数里写死为 `pending`** 的 —— 客户端连传都传不进去。

匿名身份：首次进入广场时会派生一个**本机指纹**（存在 `localStorage`，与 IP 无关），界面上显示为「匿名·K7Q2」这样的随机后缀，
旁边标注归属地（如「广东·深圳」，精确到市）。后缀和归属地都只用于展示；真正用于「认领自己帖子」的是这个指纹，
服务端只存 `md5` 前 16 位，列表接口只回 `mine: true/false`，**别人的指纹拿不到，也冒充不了**。

> IP 只参与归属地估算，**不掺进指纹**。早先版本是「IP 优先、拿不到才退回本机」，
> 结果归属地接口一超时，同一个人的 key 就变了，刷新后连自己刚发的帖子都删不掉。
> 归属地**只走 `api.ip.sb/geoip` 一个源**。之前是三家并行竞速，快是快，但同一台设备会在
> 「广东」和「广东·深圳」之间来回跳，城市一级更是三家各说各的 —— 要精确到市就只能固定一家。

发帖配额：**每人每天 3 条帖子、20 条回复**，按自然日算。用量记在一本只增不减的账本里
（`lib/visitor-ledger.ts`），**删掉自己的帖子 / 回复也不退额度** —— 否则「发满三条 → 全删掉 → 再发三条」
就是免费无限发。账本按「访客 × 自然日」分行，同一天里换个人不占用上一个人的额度。

改昵称：**每人每天一次**，同样记在这本账上。"只显示剩余额度，用完之后不再出现任何提示文字"——
拦截只发生在按下的那一刻（一个 toast）。

拥抱：同一个人对同一条只占一次数，**可以再点一次取消**（`hugPost(id, visitor, want)`，
云端对应 `moodbox_square_hug(p_undo)`）。按钮有 700ms 冷却，挡手滑连点。

回复的限制：**最多 200 字**（按字符数算，一个 emoji 算 1 字），发送前会过一次敏感词扫描 ——
命中时把命中的词打码后提示「换个说法」，并禁用发送按钮。自伤相关表达不走这套逻辑，仍归 `lib/crisis.ts`，只提示不拦截。

### 主题

- 默认跟随系统 `prefers-color-scheme`；页头右侧的太阳 / 月亮按钮可手动锁定白日或星空，选择写入 `localStorage`；
- 首帧由 `<head>` 里的内联脚本写入 `data-theme`，因此不会出现「先白一下再变暗」；
- 颜色全部走 CSS 变量，切主题不触发 React 重渲染，也不会产生水合差异。

### 内容后端：树洞广场可接 Supabase

内容类数据（故事、帖子、信件）走一层 `ContentBackend` 接口，三种实现：

| 实现 | 触发条件 | 广场数据在哪 |
| --- | --- | --- |
| `localBackend` | 默认 | 本机 IndexedDB |
| `supabaseBackend` | 配了 `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` | **Supabase 云端** |
| `createHttpBackend` | 配了 `NEXT_PUBLIC_MOODBOX_API_BASE` | 自建 REST（预留） |

只有广场会上云（它是唯一多人共享的内容）；心事信箱、开心罐、内置故事仍留本机。
接口约定写在 `src/lib/backend/http.ts` 顶部。

**接入步骤见 [`SUPABASE.md`](./SUPABASE.md)**，建表脚本在 `supabase/schema.sql`。
配好之后如果想临时退回本机模式（离线演示），在浏览器控制台执行
`localStorage.setItem('moodbox-force-local', '1')` 并刷新即可，页面文案会跟着变成「仅在本机」。
接上之后，管理员审核会从「前端遮罩」变成真正的服务端校验 —— 这点在第七节有说明。

## 三、技术栈

| 技术 | 用途 |
| --- | --- |
| Next.js 15（App Router） | 路由、服务端渲染、静态预渲染 |
| React 19 | UI 与状态 |
| TypeScript（strict + `noUncheckedIndexedAccess`） | 全量类型约束 |
| Tailwind CSS v4 | 设计 token 与布局，视觉细节写在 `globals.css` |
| Motion for React | 入场、悬停、面板、碎裂、星屑等离散动画 |
| lucide-react | 线性图标 |
| IndexedDB（`idb`） | 本地持久化（记忆、图片、情绪记录、故事、信件、捏爆状态；未接云端时还包括帖子） |
| Supabase（`@supabase/supabase-js`） | **可选**：树洞广场的帖子 / 回复 / 拥抱 / 审核 |
| date-fns | 日期计算与中文格式 |
| HTML5 Audio | 背景音乐（无第三方播放器） |
| Vitest + Testing Library | 单元 / 组件测试 |
| Playwright | 主要用户流程的端到端测试 |

依赖选择说明：
- `idb`（约 1KB）只是 IndexedDB 的 Promise 封装，避免手写大量 `onsuccess` 回调；
- `date-fns` 按需引入，用于月视图、近七日、中文日期格式；
- `@supabase/supabase-js` 只在配置了 Supabase 时才会真正发请求，但会被打进包（约 50KB gzip），换来的是「不用自己写后端」；
- 没有引入任何 UI 组件库、状态管理库、CSS-in-JS 或主题库 —— 双主题靠一份 CSS 变量表实现，多一个依赖反而更容易打架。

## 四、快速开始

```bash
# 1. 安装依赖
npm install

# 2. 启动开发服务器（默认 http://localhost:3000）
npm run dev

# 3. 生产构建与启动
npm run build
npm start
```

其它脚本：

```bash
npm run typecheck   # tsc --noEmit
npm run test        # Vitest 单元 / 组件测试
npm run test:e2e    # Playwright 端到端测试（默认端口 3107）
```

要求：Node.js ≥ 20（开发使用 22.22），npm ≥ 10。

### 可选：把树洞广场接到 Supabase

不配也能完整运行（广场数据在本机）。想让它变成"真的多人共享"：

```bash
# 1. 建 Supabase 项目 → SQL Editor 执行 supabase/schema.sql
# 2. 根目录创建 .env.local
echo "NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co" >> .env.local
echo "NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi..." >> .env.local
# 3. 必须重新构建（这两个值是构建期内联的，只重启不生效）
npm run build && npm start
```

打开 `/square`，副标题出现「树洞广场已接入 Supabase · 帖子存在云端项目 xxx」就成功了。
完整步骤、安全模型、报错对照表见 **[`SUPABASE.md`](./SUPABASE.md)**。

> 端到端测试默认复用系统已安装的 Chrome（`playwright.config.ts` 中的 `channel: 'chrome'`）。
> 若机器上没有 Chrome，执行 `npx playwright install chromium` 后删掉该行即可。
> 端口可用 `E2E_PORT` 环境变量覆盖，避免与本机其它项目冲突。

## 六、数据存储原理

- 使用浏览器 IndexedDB，数据库名 `moodbox`，当前版本 **`3`**，七个对象仓库（接上 Supabase 后 `posts` 会被清空且不再写入）：

| 仓库 | 内容 | 主键 / 索引 |
| --- | --- | --- |
| `memories` | 快乐记忆（含图片 Blob） | `id` / `by-date`、`by-updated` |
| `emotionLogs` | 当天的情绪记录 | `id` / `by-date` |
| `stories` | 治愈故事 | `id` / `by-created` |
| `posts` | 树洞帖子（**只在未接 Supabase 时使用**） | `id` / `by-created`、`by-status` |
| `letters` | 心事信件 | `id` / `by-created` |
| `capsules` | 时光信箱 | `id` / `by-open` |
| `bursts` | 被捏爆的情绪球（只存 emotionId） | `emotionId` |

- **v1 → v2 迁移**：`upgrade(db, oldVersion)` 里用 `if (oldVersion < 2)` 一次性建好新增的 5 个仓库，并在同一次升级里写入内置故事。写在迁移里（而不是每次启动检查）意味着**用户删掉的内置内容不会被自动补回来** —— 那会被当成「删了又回来」的 bug。
- **v2 → v3 迁移**：广场改为云端后，本机 `posts` 仓库不再被读取。迁移时**只有配置了 Supabase 才清空它**，纯本地模式的数据原样保留（那是唯一副本）。
  ⚠️ 升级回调里**不能 `await`**：一旦 await，版本变更事务就不再是「当前事务」，后续 `db.transaction` 会抛 `A version change transaction is running`，整个数据库打不开。正确做法是在传入的 `tx.objectStore(...)` 上同步发请求。
- 图片以 **Blob** 存入 IndexedDB（先在本地用 canvas 压到最长边 ≤1600px、JPEG q=0.82），不使用 base64，也不会写入 `localStorage`。
- 页面读取时通过 `URL.createObjectURL` 生成预览，并按 Blob 缓存（`WeakMap`），避免重复创建。
- 默认所有记录都只存在于当前浏览器 / 设备，**没有账号、没有云同步**；只有**主动配置 Supabase** 之后，广场的帖子才会写到云端（其余内容仍然只在本机）。
- 「清空数据」是**语义化**的：清空记忆 / 情绪记录 / 信件 / 时光 / 捏爆状态，只删除用户自己发的帖子与故事 —— 弹层里逐项列出了会删什么。接了 Supabase 之后，弹层会明确写着「广场的帖子不在这里删」，要清空云端得跑 `supabase/reset-square.sql`。
- 配额与异常：`QuotaExceededError` 会翻译成「存储空间不足」的人话提示；不支持 IndexedDB 时进入只读提示状态而不是白屏。

隐私提示（站内「备份与隐私」也有同样说明）：清除浏览器网站数据、无痕模式、更换设备都可能导致记录丢失，建议定期导出 JSON 备份。

### 自伤倾向识别

`src/lib/crisis.ts` 里是一组**关键词正则**（6 类：想死 / 自杀 / 自伤 / 具体方式 / 告别语气 / 强烈无价值感），发帖与回复前扫一遍。三条不可退让的原则：

1. **只提示，不拦截** —— 看完提示仍可照常发布。把话堵回去，往往比让它留在树洞里更危险；
2. **不做诊断** —— 文案是「我有点担心你」，没有任何结论性措辞；
3. **给出真实号码** —— 12356、010-82951332、400-161-9995，而不是一句「请寻求帮助」。

客户端匹配只能算体验层的第一道提示。接上后端后，**识别与审核必须放在服务端**，不能把它当成唯一防线。

## 七、背景音乐配置

当前曲目：**《Long Day》—— PurrpleCat（Pixabay）**，无人声纯音乐，文件位于 `public/audio/long-day.mp3`，随项目一起分发，授权遵循 [Pixabay Content License](https://pixabay.com/service/license-summary/)。

更换曲目：

1. 把音频放到 `public/audio/long-day.mp3`（或换成自己的文件名）；
2. 修改 `src/lib/audio-config.ts` 中的 `src`、`title`、`artist`、`defaultVolume`；
3. 刷新页面，点击页头「音乐」即可开启。

行为说明：
- 首次进入**不会**自动播放（尊重浏览器 autoplay 策略与用户意愿）；
- 音量偏好写入 `localStorage`，但「是否播放」每次都需要用户主动点击；
- 播放器挂载在根布局，站内切换页面不会中断；
- 开启/关闭有 1.4s 淡入淡出，默认循环；
- 页面加载时就会探测音源（`preload="metadata"`），文件不存在时右上角音乐按钮出现暖色小点，面板显示「未接入」并给出文件路径；此时点播放不会卡在「准备中」，控制台会有一条预期内的 404，网站其它功能不受影响；
- `check-audio.mjs` 专门验证这条降级路径：`node scripts/check-audio.mjs`。

## 十、已知边界

- **默认**数据仅存本地、不跨设备同步；想跨设备只能接 Supabase（只影响广场，其余内容仍是本机的）；
- **管理员口令只在前端校验**，不是权限系统，只用于演示审核流程；真实上线必须把权限与审核挪到服务端；
- 自伤识别是基于关键词的启发式匹配，会漏也会误报；它只用于"轻轻问一句"，不构成任何判断；
- 树洞广场同一条帖子在本地可以重复拥抱（没有账号体系，无法去重），换设备后计数不通用；
- 图片统一转码为 JPEG，会丢失透明通道；
- 浏览器隐私模式下 IndexedDB 可能不可用，此时会展示明确提示而不是假装保存成功；
- 情绪统计仅基于主动记录，**不会**推断未记录日期的心情，也不提供任何心理评估结论；
- 宽度小于 1024px 时首页只呈现 7 颗球（其余 4 种在更宽窗口可见），这是为避免情绪球压住中央文案做的取舍；
- 背景音乐需自行提供授权音源，仓库中只有一个空的 `public/audio/README.md`；
- 广场接上 Supabase 后：**没有身份体系**（匿名访客可以无限发帖，靠审核兜住）、**拥抱可以刷**（同一浏览器能反复抱，去重就要追踪用户，本项目的取舍是宁可被刷也不追踪）、**没有实时推送**（别人发的新帖要刷新才看到）。完整清单见 `SUPABASE.md` 第九节。
